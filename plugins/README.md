# 插件约定

本仓不提供插件运行时、不自动发现插件、不执行任何第三方代码。"插件"在这里只是一个约定：**任何能把内容写成符合下面契约的 `.md` 文件、丢进某个已注册 collection 的 root 目录里的脚本**，都能喂给 `scoped-kb index`，不需要改核心代码一行。

这个目录下只放文档（你要自己写采集脚本、转写脚本等），`douyin-favorites/` 是一个范例，只讲方法，没有可运行代码。

## 一个 `.md` 文件要满足的契约

1. **文件位置**：落在某个已注册 collection 的 root（或其子目录）下，且不被该 collection 的 `excludes` 排除。一个采集脚本通常固定写一个目录，由你在 `machine-sources.json` 或某个仓库的 `collections.json` 里把这个目录注册成一个 collection。

2. **分块边界是二级标题 `## `**：`scoped-kb index` 按 `## ` 切块，每块独立参与向量化和排序。写插件时尽量让每个 `## ` 小节本身可以独立被检索到（自成一段意思），不要指望跨小节的上下文会被保留。

   - 不超过 60 个字符（含标题行，去掉首尾空白后）的小节会被**静默丢弃**，不会报错也不会索引——写极短的摘要段落时注意这一点。
   - 单个小节超过 1600 个字符会被自动按句读（。！？；.!? 等）再切一刀，标题会保留在每一段前面；没有句读的超长单段不会被切开，可能超出 embedding 模型的上下文上限；这是兜底，不要依赖它，尽量让小节本身不要写得过长。

3. **可选 YAML frontmatter**（文件开头 `---` 到 `---` 之间），只认顶层键值对，不支持嵌套结构。常用字段（由 `config.json` 的 `provenance_fields` 决定实际渲染哪些，默认三个）：

   ```yaml
   ---
   trust_tier: T1          # 建议只用 T1/T2/T3，渲染层对这三个值有预设标签；其它字符串会原样显示但不会被识别成已知等级
   source_url: https://...  # 原文链接；不是链接的描述性文字会被渲染层替换成"非链接来源"，防止夹带联系方式被原样吐给外部 agent
   captured_at: 2026-01-01  # 采集日期，自由格式字符串
   ---
   ```

   frontmatter 不会进 embedding，只在 `scoped-kb search` 渲染结果时回读。没写任何字段也完全合法：出处行只显示 collection 的归属标签（如「自有产出·笔记」）；连归属标签也没有时显示"未标注"。

4. **`<!-- no-index -->` 标记整段跳过**：把这个字符串放进某个 `## ` 小节内（通常紧跟在标题下面），这一整个小节就不会参与索引，但文件本身仍然留着给人读。典型用途是语音转写的完整逐字稿——量大、口语化、重复度高，全量入库会把真正验证过的结论挤出检索结果页，但你可能还想留着原文供回听核对。参考 `examples/notes/knife-skills-class-transcript.md`。

5. **归属（`kind_default`）是 collection 级的，不是文件级的**：一个 collection 里所有文件在出处渲染里显示同一个"自有产出 / 外部采集"标签，这个标签在注册 collection 时由 `kind_default` 字段定一次（`note`/`decision`/`session_digest`/`memory`/`digest`/`reference` 渲染成"自有产出·…"，`raw` 渲染成"外部采集"）。如果你的采集脚本既抓外部内容又有自己二次整理的结论，把两者分别落进两个不同的 collection（哪怕物理上是同一父目录下的两个子目录），不要试图用单个文件的 frontmatter 覆盖 collection 级的归属——`kind_default` 本来就设计成"仓库声明一次，不逐文件覆盖"。

6. **不要跟符号链接较劲**：索引时会检查文件的真实路径是否仍在它所属 collection 的 root 内，跑到 root 外面的符号链接会被跳过并计入 `index` 输出里的"跳过 N 个文件"提示，不会报错中止、也不会悄悄把域外内容收进来。

## 典型接线方式

1. 写一个独立脚本（不在本仓范围内），定期把源内容转成符合上面契约的 `.md` 文件，固定写到某个目录；
2. 把这个目录注册成一个 collection（单域用户一般不需要这步，`scoped-kb init` 已经把笔记目录注册好了；多域场景按 `examples/config/multi-domain/` 的结构手写）；
3. 脚本跑完后调用 `scoped-kb index`（增量，只对新增/变化的内容重新向量化）。

脚本本身的调度（定时任务、监听文件变化）不在本仓范围内，用你平台上惯用的方式（cron / launchd / systemd timer）接上即可。
